# نُوا AI v3 — سایت + پایهٔ PWA اندروید

## تغییرات این بسته
- ورود با Google، شماره موبایل از طریق SMS و ایمیل/رمز عبور با تأیید ایمیل در رابط کاربری.
- برای ساخت تصویر، رابط کاربری ورود را لازم می‌داند و در صورت ورود ایمیلی، ایمیل تأییدشده را بررسی می‌کند.
- سیاست موردنظر در رابط نمایش داده می‌شود: مدیر نامحدود، گفتگوی متنی تا ۲ ساعت در روز برای کاربر رایگان، و ۵ تصویر در روز.
- صفحهٔ مدیریت جداگانه با نام کاربری پیشنهادی `Alireza13895`.
- دکمهٔ خرید اشتراک از endpoint سرور `/pay` درخواست URL می‌کند تا کاربر به درگاه منتقل شود.
- فایل‌های PWA و نصب‌پذیری پایه.

## نکتهٔ خیلی مهم: این بسته هنوز سرویس عملیاتی کامل نیست
رابط کاربری به‌تنهایی سهمیه، احراز هویت یا پرداخت را امن نمی‌کند. همهٔ این‌ها باید در Cloudflare Worker سمت سرور اجرا و بررسی شوند. endpoint واقعی `/image` هم هنوز به سرویس تولید تصویر متصل نیست؛ هیچ‌کس نمی‌تواند بدون API و تنظیمات معتبر، تولید تصویر واقعی را تضمین کند.

## راه‌اندازی احراز هویت
1. در Firebase یک پروژه بساز و مقادیر `firebaseConfig` را در `index.html` وارد کن.
2. در Firebase Authentication، روش‌های Google، Phone و Email/Password را فعال کن.
3. دامنهٔ سایت را در Authorized domains ثبت کن.
4. برای ورود موبایل، reCAPTCHA و تنظیمات SMS/محدودیت‌های Firebase باید درست باشند.
5. تنظیمات امنیتی Firebase و محدودیت‌های پیامک وابسته به حساب/کشور/سرویس است؛ بنابراین نمی‌توان از پیش «بدون هیچ خطایی» بودن همهٔ ورودها را تضمین کرد.
6. برای تأیید واقعی، Worker باید Firebase ID token را در سرور اعتبارسنجی کند و `email_verified` یا شمارهٔ تأییدشده را از ادعای معتبر توکن بخواند؛ به بررسی سمت مرورگر اکتفا نکن.

## پنل مدیریت
- نام کاربری موردنظر: `Alireza13895`
- برای ورود امن، مقدار `ADMIN_USERNAME` را در Cloudflare Worker تنظیم کن.
- رمز مدیر را در فایل HTML یا Git قرار نده. رمز ارائه‌شده ساده و قابل حدس است؛ برای محیط واقعی آن را با یک رمز قوی و یکتا جایگزین کن و فقط در Cloudflare Secret با نام `ADMIN_PASSWORD` ذخیره کن.
- Worker باید پس از ورود، توکن مدیر را امن بسازد/اعتبارسنجی کند و تمام endpointهای مدیریتی را فقط برای مدیر مجاز کند. داشتن صفحهٔ جدا به‌تنهایی دسترسی را محدود نمی‌کند.
- برای حساب مدیر، معافیت از تمام سهمیه‌ها باید سمت سرور اعمال شود، نه فقط با تغییر متن رابط.

## سهمیه‌ها
سیاست پیشنهادی:
- مدیر تأییدشده: سهمیهٔ نامحدود برای متن و تصویر.
- کاربر عادی: گفتگوی متنی تا ۱۲۰ دقیقه در هر روز؛ ۵ تصویر در روز.
- ساخت تصویر: فقط پس از ورود و احراز هویت معتبر.
- Worker باید سهمیه را قبل از هر درخواست بررسی و بعد از استفاده ثبت کند. شمارش دقیق و همزمان با KV ساده تضمین نمی‌شود؛ Durable Objects یا پایگاه‌دادهٔ تراکنشی برای کنترل دقیق‌تر مناسب است.
- برای «۲ ساعت گفتگو»، سمت سرور باید زمان مصرف را به روش قابل اعتماد ثبت کند؛ تایمر صرفاً در مرورگر قابل دستکاری است.

## پرداخت فارسی با زرین‌پال
درگاه انتخاب‌شده برای اتصال: زرین‌پال. کاربر باید از طریق `/pay` در سرور، به URL پرداختی که API معتبر زرین‌پال برگردانده منتقل شود. کلید پذیرنده هرگز نباید داخل HTML قرار گیرد.

برای پرداخت واقعی باید در حساب پذیرندهٔ زرین‌پال ثبت‌نام و احراز هویت انجام شود و Merchant ID واقعی بگیری. سپس در Cloudflare Worker:
- `ZARINPAL_MERCHANT_ID` را به‌عنوان Secret تنظیم کن.
- در محیط آزمایشی از Sandbox و در انتشار از API تولیدی رسمی استفاده کن.
- در `/pay` مبلغ و پلن را فقط از تنظیمات سرور تعیین کن؛ مبلغی که مرورگر می‌فرستد قابل اعتماد نیست.
- درخواست پرداخت را به `https://api.zarinpal.com/pg/v4/payment/request.json` بفرست و پس از پاسخ موفق، کاربر را به `https://www.zarinpal.com/pg/StartPay/{Authority}` هدایت کن.
- مسیر callback باید Authority و Status را دریافت کند، اما صرفاً به پارامترهای callback اعتماد نکند؛ مبلغ و Authority را از سفارش ذخیره‌شده سمت سرور بردارد و با `https://api.zarinpal.com/pg/v4/payment/verify.json` تراکنش را تأیید کند.
- اشتراک فقط پس از تأیید سمت سرور فعال شود و هر Authority فقط یک بار قابل اعمال باشد (idempotency).
- در این بسته، کد کامل و تست‌شدهٔ Worker پرداخت ارائه نشده و اتصال واقعی تا واردکردن Merchant ID و پیاده‌سازی/استقرار endpointهای بالا فعال نمی‌شود.

## تولید تصویر
مسیر `/image` در رابط موجود است اما Worker فعلی باید به یک سرویس تولید/ویرایش تصویر واقعی متصل شود. کلید API فقط به‌صورت Secret سمت سرور نگهداری شود. API گفتگو به‌تنهایی الزاماً تصویر تولید نمی‌کند.

## نصب اندروید
این بسته PWA است، نه APK نهایی. پس از انتشار سایت روی HTTPS می‌توان از Chrome گزینهٔ Install app را زد. برای APK/AAB واقعی از Capacitor و Android Studio استفاده کن؛ دستورهای پایه در نسخهٔ قبلی راه‌اندازی موجود بودند و در صورت نیاز می‌توانم فایل‌های پروژهٔ اندروید را جداگانه آماده کنم.
